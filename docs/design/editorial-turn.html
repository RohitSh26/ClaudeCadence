Done. New GET /orders.csv endpoint mirrors the existing index filters and returns the receipt column order.

The JSON export at /orders.json is untouched — the CSV path branches inside respond_to so the wire format is the only difference. All 14 request specs pass, including 8 new ones that cover empty results, paginated CSV (we stream rather than paginate), and the date-range edge cases.

  • Status filter accepts the same values as the index page (paid, refunded, pending, void).
  • Date range uses placed_at, inclusive on both ends. Times are normalised to the account's reporting timezone.
  • Per-row totals come from Order#summary_for_export, which I extracted from the existing SummaryView so the CSV and the on-screen total never drift.

Two things worth flagging before merge: large exports stream chunked, so cancelling the request mid-download leaves a partial file. And the CSV is unsigned — if you want a download to be revocable, we should add a one-shot token at the endpoint.
